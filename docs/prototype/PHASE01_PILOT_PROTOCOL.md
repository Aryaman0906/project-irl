# Phase 0.1 Feasibility Pilot Protocol

**Status:** protocol only; no recruitment or results. **Duration:** 1–2 weeks. Use synthetic profiles until participant permission, safeguarding, privacy notice, retention/deletion procedure, facilitator training, and professional review are approved. A guardian checkbox alone is not legal compliance.

## Ordered protocol

1. Confirm Android checklist below with synthetic data. Resolve data loss, duplicate XP, and interruption defects first.
2. With appropriately permissioned participants, explain local storage, optional reflection, self-report, non-cash XP, withdrawal, and facilitator note-taking. Do not collect names in the app.
3. Days 1–3: test only the core loop. Ask the participant to choose, read, start, leave the app, return, complete/cancel, optionally reflect, and find history without coaching.
4. Days 4–10/14: allow voluntary reuse. Do not prompt a quota or punish missed days. Ask whether easy tasks are being repeated mainly for XP.
5. Only after core comprehension, show **Explore concepts** as a separate research stimulus. Record category preference, confusion, or pressure; do not test payment.
6. Delete local data at withdrawal/end according to the approved protocol. Record incidents and counter-evidence; do not invent outcomes.

## Measures and interpretation

| Measure | Source | Interpretation boundary |
|---|---|---|
| Flow completed without coaching; help points | Facilitator observation | App usability only |
| Another activity chosen voluntarily | Observation plus participant explanation | Choice, not habit formation |
| Explanation of `SELF_REPORTED` and non-cash XP | Participant paraphrase | Comprehension, not honesty |
| Easy-task repetition and reason | Stored attempt pattern plus self-report | Possible incentive effect, not deception |
| Usefulness rating and app interaction time band | Participant report/observation | More XP or longer sessions is not proof of improvement |
| Data-loss, duplicate-award, reset, interruption incidents | App state/checklist | Reliability evidence |
| Offline behaviour | Participant report unless separately observable | Keep distinct from observed app events |

## Physical Android checklist

- [ ] Install a debug build without overwriting an existing test install; note app/version and device/Android version.
- [ ] Complete a quest, force-stop, reopen, and confirm the attempt, reflection choice, history, and XP persist exactly once.
- [ ] Start a quest; background, lock/unlock, foreground, and confirm timing remains labelled as elapsed time rather than verification.
- [ ] Start, swipe-kill, reopen, and reboot. Confirm an interrupted recovery screen appears and permits resume/cancel without XP.
- [ ] Change device time backward and across local midnight; confirm uncertainty and daily limits. Restore automatic time afterward.
- [ ] Rapidly tap completion and navigate back/forward; confirm one completion and one award.
- [ ] Trigger/approximate low-storage write failure where feasible; confirm no completion-without-award partial state.
- [ ] Complete three different quests and a repeat on one local day: 30 XP total; repeat practice is recorded with 0 XP.
- [ ] Check TalkBack labels, focus order, 200% font scaling, portrait/landscape, small screen, and contrast.
- [ ] Confirm **Explore concepts** has no purchase/redeem/checkout/payment path and selections do not change XP.
- [ ] Delete all local data, force-stop/reopen, and confirm attempts, reflections, active session, XP, and selections remain empty.
